# Safe AMM Integration Plan (Backend/CLI Focus)

## Overview

Integrate custom AMM contracts, indexers, and SDK as optional extensions without breaking existing Uniswap/Balancer/Curve indexers, MongoDB collections, or UI components. All new features are opt-in via feature flags.

**Critical Requirements:**

- **No fallback/dummy data** - Fail fast with clear errors showing WHERE the error occurred (file, line, function, stack trace)
- **CLI error visibility** - All errors must be visible in CLI with full context using `errorLogger.ts`
- **Backend-focused** - Focus on CLI tools, indexers, and backend services, not API/UI
- **Error propagation** - Errors should propagate up and stop execution, not be silently caught
- **Error context** - Every error must include: file path, line number, function name, operation context

## Phase 1: Foundation (Non-Breaking)

### 1.1 Contracts Structure

- Add `contracts/AMM/` directory with custom AMM contracts:
  - `AMMFactory.sol` - Factory for deploying pools
  - `AMMPool.sol` - Core pool logic (V2-style or V3-style)
  - `AMMRouter.sol` - Router for swaps and multi-hop routing
  - `AMMLiquidityManager.sol` - Helper for liquidity management
  - `AMMPositionNFT.sol` (optional) - NFT positions if using V3-style
- Keep existing `contracts/UniswapV2Factory.sol` untouched
- Update `hardhat.config.mjs` to compile both directories (no changes to existing compilation)
- Add `scripts/deploy-amm.js` for local testing (doesn't affect existing deployments)
- Export ABIs to `src/server/abi/AMM/` following existing pattern (UniswapV2Factory.json, UniswapV2Pair.json)

### 1.2 MongoDB Collections (New, Non-Conflicting)

- Extend `src/lib/db/mongo.ts` to add new collections:
  - `ammPoolsCollection` → collection name: `amm_pools` (not `pool_metadata`)
  - `ammSwapsCollection` → collection name: `amm_swaps` (not `pool_events`)
  - `ammPositionsCollection` → collection name: `amm_positions`
  - `ammLiquidityEventsCollection` → collection name: `amm_liquidity_events`
- Use `amm_` prefix in collection names to avoid conflicts with existing `pool_metadata` and `pool_events`
- Add indexes following existing pattern (see lines 48-55 in mongo.ts)
- Add getter functions: `getAmmPoolsCollection()`, `getAmmSwapsCollection()`, etc.

### 1.3 Types Extension

- Extend `src/types/amm.ts` with new interfaces:
  - `AMMPoolMetadata` (extends PoolMetadata pattern but for custom AMM)
  - `AMMSwap` (swap events specific to custom AMM)
  - `AMMPosition` (position data if using V3-style)
  - `AMMLiquidityEvent` (mint/burn events)
- Keep existing `PoolMetadata` and `PoolEvent` unchanged for backward compatibility

### 1.4 Catalog Extension

- Add custom AMM entry to `src/server/catalog/amm.json`:
  ```json
  "custom_amm": {
    "factory": null  // Set when deployed
  }
  ```


## Phase 2: Indexers (Parallel, Non-Interfering)

### 2.1 Custom AMM Indexer

- Create `src/server/indexers/amm/customAmm.ts` following existing pattern:
  - Export `startCustomAmmIndexer(): Promise<void>`
  - Use same structure as `uniswapV2.ts` and `uniswapV3.ts`
  - Subscribe to `PoolCreated` events from custom AMM factory
  - Subscribe to `Swap`, `Sync`, `Mint`, `Burn` events from pools
  - Store to new MongoDB collections (`amm_pools`, `amm_swaps`) not `pool_metadata`/`pool_events`
  - Use `getProvider()` from `src/server/modules/provider.ts`
  - Use `registerPool()` from `src/server/market/ammEngine.ts` (if compatible) or create separate registry
  - Add feature flag `ENABLE_AMM_CUSTOM` in `src/lib/config.ts` (default: false)
  - Follow error handling pattern with `logErrorWithConsole` from `src/server/utils/errorLogger.ts`

### 2.2 Historical Backfill

- Create `src/server/indexers/amm/customAmm.historical.ts` for backfilling
- Use same RPC provider pattern as existing indexers (see uniswapV2.ts lines 135-174)
- Add npm script to `package.json`: `"ingest:amm:historical": "tsx src/server/indexers/amm/customAmm.historical.ts"`

### 2.3 Integration into Server Startup

- Add to `src/server/legacy.ts` after line 152 (after other AMM indexers):
  ```typescript
  import { startCustomAmmIndexer } from './indexers/amm/customAmm';
  // ... in main() function:
  if (cfg.ENABLE_AMM_CUSTOM) {
    console.log('🏦 Starting Custom AMM indexer...');
    await startCustomAmmIndexer();
  } else {
    console.log('🔒 Custom AMM indexer disabled (ENABLE_AMM_CUSTOM=false)');
  }
  ```

## Implementation Notes

- **Backward Compatibility**: All new features are opt-in via `ENABLE_AMM_CUSTOM=false` (default)
- **Database**: New collections use `amm_` prefix (`amm_pools`, `amm_swaps`) to avoid conflicts with `pool_metadata`, `pool_events`
- **Indexers**: Run in parallel, don't interfere with existing Uniswap/Balancer/Curve indexers
- **Contracts**: Deploy separately, don't replace existing Uniswap contracts
- **Catalog**: Add entry to `amm.json` but don't modify existing entries
- **UI**: Extend existing components, add new tabs as optional
- **Testing**: Add new test suites without removing existing ones
- **Patterns**: Follow existing code patterns:
  - Use `getProvider()` from `src/server/modules/provider.ts`
  - Use `logErrorWithConsole()` for error handling
  - Use `config` from `src/lib/config.ts` for feature flags
  - Use MongoDB collections via getters in `src/lib/db/mongo.ts`
